# v2.4.1 Release Hardening

Released: 2026-08-27

## Summary

v2.4.1 closes release-blocking gaps discovered during the final adversarial audit of the
v2.4 runtime. It preserves v2.4 protocol behavior while making its persistence,
inspectability, provider defaults, and public-source gate match the documented contract.

## Changes

- Accepts the council protocol's bounded `{review: text}` peer-review records while
  retaining compatibility with legacy string review maps.
- Adds real-protocol persistence coverage so all six named protocols must survive the
  complete orchestrator-to-`SessionStore` path.
- Shows protocol-specific evidence in both the React stage view and verbose CLI, including
  debate arguments/rebuttals, red-team critiques, specialist verification, tournament
  matchups, council reviews, and auto/decomposition records.
- Uses provider-qualified `openai/gpt-5.5` and `deepseek/deepseek-chat` OpenRouter defaults.
  Leaving `OPENROUTER_MODEL` empty preserves per-role defaults; native DeepSeek continues
  to use `DEEPSEEK_MODEL=deepseek-chat`.
- Extends the release scanner to reject common provider-token shapes, role-specific API
  key assignments, private credential files, and alternative lockfiles that could override
  the audited npm lock.
- Keeps scanner findings non-echoing: failures identify only the source and rule code.

## Verification

The release gate covers protocol execution and persistence, API contracts, frontend/CLI
stage rendering, scanner negative fixtures, version synchronization, Python/frontend
dependency audits, immutable GitHub Actions, and fresh-history secret scanning.
