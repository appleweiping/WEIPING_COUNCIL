# v2.4 Protocol Fidelity and Resilience

Released: 2026-08-23

## Why This Release Exists

In v2.3, smart routing ran before the selected protocol. A simple debate could silently
become a single-model answer, while a complex red-team request could become task
decomposition. The response remained inspectable at the model-call level, but the product
did not reliably honor the user's workflow choice.

v2.4 makes that contract explicit: named protocols are authoritative, while a new `auto`
mode is the only mode allowed to choose a cheaper or decomposed execution path.

## Changes

- Added `auto` across REST, CLI, and React UI.
- Added a redacted `routing` object to API responses and saved artifacts. It records mode,
  requested and selected protocol, tier, assigned member IDs, routing reason, difficulty,
  and decomposition state when applicable.
- Refactored the orchestrator so explicit protocols never invoke the smart classifier or
  task decomposer.
- Passed recalled/user context through every protocol, while isolating it as untrusted
  user-level reference context rather than system instructions.
- Added bounded provider concurrency, timeouts, attempts, exponential backoff with jitter,
  `Retry-After` support, and status-aware retry classification.
- Treats classifier scores and provider failure placeholders as untrusted input: difficulty
  is finite and bounded, and a failed model name such as `GPT-5.5` cannot be misparsed as
  a high-complexity score.
- Added trace evidence for HTTP status, retry delay, and retry reasons. Public evidence
  still excludes provider URLs, credentials, response bodies, and raw exceptions.
- Provider readiness now describes the settings active in the running process and rejects
  invalid HTTP endpoints or API formats instead of reporting a false-ready state.
- Runtime configuration reads only this project's exact `.env` plus process variables; it
  never walks parent directories into another checkout's private configuration.
- `/api/models` now reports each active runtime model ID, safe configuration-source label,
  API format, and readiness instead of repeating static dataclass defaults. It never returns
  provider URLs or credentials.
- Added an atomic `SessionStore` using same-directory temporary files plus `os.replace`.
  Corrupt, mismatched, path-like, or non-finite JSON artifacts are ignored safely by
  list/get operations.
- Session reads now apply one bounded, version-compatible artifact schema at get, prefix,
  and list boundaries; exponent overflow, nested non-finite values, wrong container types,
  excessive files, and isolated UTF-16 surrogates cannot reach API or CLI consumers.
  Provider-influenced lone surrogates are replaced consistently before response and save.
- Added request normalization, query/context size limits, and rejection of unknown fields.
- Added `/api/live` for process liveness and `/api/ready` for strict dependency readiness;
  `/api/health` remains a 200 diagnostic surface even when degraded.
- Made optional agentmemory recall explicitly disableable with `AGENTMEMORY_URL=`; a
  disabled optional service no longer adds latency, warnings, or degraded state.
- Removed the unused non-atomic local performance tracker and made the release guard reject
  any reintroduction of its code or `data/model_performance.json`; agentmemory remains the
  sole optional shared-memory boundary.
- Added periodic UI health refresh, route evidence, expandable model-call traces, and an
  abortable browser wait control that does not claim server-side provider cancellation.
- Routes final answers, stages, verdicts, and dissent through one safe Markdown renderer:
  remote images and raw HTML are blocked, unsafe URL schemes are removed, and explicit
  external links use no-referrer/noopener/noreferrer/nofollow protections.
- Made CLI output encoding-safe across commands, headers, spinners, and result text so
  unsupported glyphs are escaped instead of crashing legacy Windows consoles such as GBK.
- Removed ANSI/OSC, C0/C1, and bidirectional override controls from untrusted model,
  session, memory, query, and health text before terminal rendering.
- Kept the application on `httpx` while adding Starlette's supported `httpx2` client to
  the development test extra, eliminating the deprecated TestClient compatibility path.
- Made the release scan inspect a stable `git ls-files` snapshot, reject force-tracked
  generated/private paths, decode UTF-8 and UTF-16 content, and fail if files change mid-scan.
- Moved CI to the current Node 24-based v7 GitHub Actions on immutable official SHAs,
  tests the declared Node 22.18 floor, and fails on any known frontend vulnerability.
- Upgrades the Python installer toolchain before installation, runs `pip check`, and audits
  the complete installed Python environment in both CI and the local release verifier.
- Adds a native Windows CI job for the GBK-safe CLI, project-virtualenv installation, and
  foreign-working-directory launcher dry run; the Linux job retains the frontend build.

## Upstream Quality Bars

This release contains original MIT-licensed project code. It does not vendor or copy code
from the references below. The design was informed by:

- [LangGraph checkpointers](https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/checkpointers.mdx): persistence boundaries and explicit durability trade-offs.
- [OpenAI Agents SDK tracing](https://github.com/openai/openai-agents-python/blob/main/docs/tracing.md): concurrency-safe run scopes and trace/span separation.
- [Microsoft AutoGen selector group chat](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-agentchat/src/autogen_agentchat/teams/_group_chat/_selector_group_chat.py): explicit participant selection and bounded multi-agent execution.
- [LiteLLM router](https://github.com/BerriAI/litellm/blob/main/litellm/router.py): provider routing, bounded retries, and failure classification.
- [Open WebUI backend](https://github.com/open-webui/open-webui/blob/main/backend/open_webui/main.py): separating process availability from dependency readiness.

## Compatibility

- Existing named protocol IDs remain supported and now have stricter semantics.
- Existing session JSON remains readable; older artifacts simply lack `routing` and the UI
  labels those as legacy sessions.
- New v2.4 artifacts add `routing`. Consumers should ignore unknown fields as usual.
- Provider configuration remains environment-only. The new `VC_PROVIDER_*` policy values
  have safe defaults and are optional.

## Verification

The release gate covers protocol fidelity, auto routing, transient/permanent provider
errors, secret redaction, untrusted context placement, concurrent trace isolation, atomic
session replacement, corruption tolerance, API validation, health/readiness semantics,
CLI version consistency, frontend production build, and the release scan.
